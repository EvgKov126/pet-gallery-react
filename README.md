# Практична робота №2 — Компоненти та передача даних (Props)

Ця робота демонструє базові кроки зі створення галереї домашніх улюбленців на React за допомогою Vite: ініціалізація проєкту, організація структури папок, налаштування сучасних стилів (Glassmorphism, Grid) та реалізація взаємопов’язаних компонентів: `Header`, `PetCard`, `PetList`.

## Мета

- Навчитися передавати дані з батьківського компонента в дочірній за допомогою `props`.
- Опанувати деструктуризацію `props` у функціональних компонентах.
- Використовувати метод `map()` для динамічної генерації списків на основі масивів даних.
- Розуміти роль атрибута `key` при роботі зі списками в React.

## Стек і вимоги

- Node.js 20+
- Vite 7
- React 19

## Структура та ієрархія компонентів (ЛР2)

Дані передаються зверху вниз за наступною структурою:

```
App (джерело даних: PET_DATA)
├─ Header (отримує заголовок через title)
├─ Main (прокидає масив pets далі у контентну зону)
│  └─ PetList (ітерує масив через .map() та створює список)
│       └─ PetCard (отримує дані окремої тварини: name, species, age, imageUrl)
└─ Footer (отримує рік та ім'я автора для відображення)
```

## Ключові етапи реалізації

### 1. Передача даних з App
У компоненті `App.jsx` створено масив об’єктів `PET_DATA`. Він передається в компонент `Main` як пропс: `<Main pets={PET_DATA} />`. Також демонструється передача простого рядка в `Header` та `Footer`.

### 2. Компонент-посередник Main
Компонент `Main` приймає `pets` через деструктуризацію параметрів і без змін передає їх у `PetList`. Це типовий приклад "прокидання" (drilling) даних.

### 3. Рендеринг списку в PetList
Тут використовується метод `map()`. Кожен елемент масиву перетворюється на компонент `PetCard`. Важливо: кожному `PetCard` передається унікальний `key={pet.id}` для коректної роботи React з DOM.

### 4. Відображення в PetCard
Компонент отримує конкретні властивості (`name`, `species`, `age`, `imageUrl`). Він використовує їх для:
- Відображення імені та породи улюбленця.
- Рендерингу зображення через атрибут src.
- Виводу віку тварини у відповідному блоці картки.

## Результати
Після виконання роботи застосунок стає динамічним: інтерфейс будується на основі даних, а не жорстко прописаного HTML. Це готує базу для впровадження стану (`state`) у наступних лабораторних роботах.


## Як запустити локально

1) Встановіть залежності

```powershell
npm install
```

2) Запустіть режим розробки (з HMR)

```powershell
npm run dev
```

Після запуску у консолі зʼявиться локальна адреса (типово http://localhost:5173). Відкрийте її у браузері.

3) Зібрати продакшн‑білд

```powershell
npm run build
```

4) Попередній перегляд зібраної версії

```powershell
npm run preview
```
