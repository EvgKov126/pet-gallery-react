# Практична робота №4 — Рендеринг списків і умовне відображення в React

Ця робота присвячена формуванню навичок динамічного відображення колекцій даних та керування інтерфейсом залежно від стану застосунку. Основна увага приділяється методам обробки масивів та реактивному оновленню UI.

## Що змінилося порівняно з Практичною роботою №3

| Характеристика | Практична робота №3 | Практична робота №34 |
| :--- | :--- | :--- |
| **Дані** | Пряме відображення масиву | Попередня фільтрація через `filter()` |
| **Зберігання** | Базовий `map()` | `map()` з умовними перевірками |
| **Взаємодія** | Постійне відображення | Умовне відображення (Empty State) |
| **Інтерфейс** | Кнопки дії (лайк) | Кнопки фільтрації режимів (All / Liked) |

## Мета

Метою роботи є освоєння декларативного підходу до створення списків:

- `map()` як конвеєр: перетворення даних об'єктів у масив JSX-елементів.
- Атрибут `key`: використання унікальних ідентифікаторів `(id)` для оптимізації оновлень DOM та уникнення зайвих перерендерів.
- Умовний рендеринг: застосування тернарних операторів та логічного `&&` для керування станами інтерфейсу.
- Фільтрація: підготовка даних перед відображенням без мутації оригінального стану.

## Структура та ієрархія компонентів (ЛР3)

Дані та функції для їх зміни передаються зверху вниз:

```
App (Контейнерний компонент: зберігає state, фільтрує дані)
├─ Header (Презентаційний: відображає статистику вподобань)
├─ AddPetForm (Передає дані про нову тварину в App через callback-функцію.)
├─ Main (Структурний: передає відфільтровані дані)
│  └─ PetList (Презентаційний: умовний рендеринг списку або EmptyState)
│       └─ PetCard (Презентаційний: відображає одиницю даних)
└─ Footer (Статичний)
```

## Ключові етапи реалізації

### 1. Фільтрація даних перед рендерингом
У `App.jsx` реалізовано механізм створення проміжного масиву `filteredPets`. Це дозволяє змінювати відображення (показувати всіх або тільки вибраних), не змінюючи джерело даних у стані.

### 2. Застосування унікальних ключів
Кожен компонент `PetCard` отримує `key={pet.id}`. Це дозволяє React коректно ідентифікувати елементи при зміні фільтрів, що підвищує продуктивність застосунку.

### 3. Умовний рендеринг "Empty State"
Реалізовано перевірку на наявність даних: якщо після фільтрації масив порожній, замість списку карток користувач бачить інформаційне повідомлення. Це реалізовано за допомогою тернарного оператора в JSX.

### 4. Презентаційний характер компонентів
Компоненти `PetList` та `PetCard` залишаються "чистими": вони отримують дані через `props` і лише відповідають за їх візуалізацію, що відповідає кращим практикам React-розробки.

## Результати
Завдяки поєднанню методів `filter()` та `map()`, застосунок став інтерактивним інструментом, що дозволяє користувачу керувати контентом. Реалізована модель є реактивною: UI автоматично підлаштовується під актуальний стан даних.


## Як запустити локально

1) Встановіть залежності

```powershell
npm install
```

2) Запустіть режим розробки (з HMR)

```powershell
npm run dev
```

Після запуску у консолі зʼявиться локальна адреса (типово http://localhost:5173). Відкрийте її у браузері.

3) Зібрати продакшн‑білд

```powershell
npm run build
```

4) Попередній перегляд зібраної версії

```powershell
npm run preview
```
